## SpeedScale API (M2-02) — `src/components/SpeedScale.tsx`

```ts
interface SpeedScaleProps {
  value?: NaturalSpeed;                         // undefined = not rated
  onChange?: (v: NaturalSpeed | undefined) => void;
  readonly?: boolean;                           // compact bar for detail/list (M3)
}
export const SPEED_LABELS: Record<NaturalSpeed, { label: string; description: string }>;
```

Labels and descriptions, spec §2.3 verbatim:

| Value | Segment label | Description shown when selected |
|------:|---------------|---------------------------------|
| 0 | **None** | Flat. You make all the speed. |
| 1 | **Little** | Slight slope. Needs a lot of help. |
| 2 | **Some** | Some slope. Needs a bit of help. |
| 3 | **Enough** | Rolls in with speed for most tricks. |
| 4 | **Too much** | Steep. You have to scrub speed. |

- Edit form: root `View accessibilityRole="radiogroup"`; five equal `Pressable` segments (`flex: 1`),
  `accessibilityRole="radio"`, `accessibilityState={{ checked }}`, `accessibilityLabel="<label>: <description>"`.
  Label text 12–13 pt, `numberOfLines={1}` except "Too much" (may wrap). Tap → `onChange(v)`; tap the selected one →
  `onChange(undefined)`. Description line under the row; "Not rated" when `value === undefined` (test `=== undefined`,
  never `!value`: 0 = None is real). Selected segment filled `palette.blue[500]`, white text; others `gray[100]`.
- Readonly: root `accessibilityLabel="Natural speed: <label>"`, no radio roles, not pressable; five small cells
  `testID="speed-cell-0..4"` (ids stay stable), cell i filled when `value !== undefined && i <= value`, marked with
  `accessibilityState={{ selected: filled }}` (test reads `props.accessibilityState`). Word beside the bar.
  `value` undefined in readonly → renders `null` (caller hides the row).
- Filled colour `palette.blue[500]` both forms; no red/green, no yellow.
- **Range mode deferred to M5** (Filter sheet, §2.5). Not built or stubbed now; M5 adds `range?: [low, high]` props.
- Export from `src/components/index.ts`.

## PhotoGrid API (M2-03) — `src/components/PhotoGrid.tsx`

```ts
interface PhotoGridProps {
  photos: Media[];                                   // already in display order (spotPhotos), primary first
  onPressPhoto?: (index: number) => void;
  renderBadge?: (media: Media, index: number) => ReactNode;  // ✕ remove (edit), 'new' mark (staged add)
  trailing?: ReactNode;                              // '+' tile (edit); rendered as the last tile
}
```

- Tile 0 (hero): `width: '100%'`, `aspectRatio: 4 / 3`. Tiles 1…n: rows of three square tiles (`aspectRatio: 1`),
  `spacing.xs` gaps. Layout: hero, then a `flexDirection: 'row', flexWrap: 'wrap', gap: spacing.xs` container; tile
  width `(W - 2 * spacing.xs) / 3` with W from the row's `onLayout` (before layout: `'31%'`, so the first frame is
  already three across). Exact sizing is the builder's (§10); tests pin only `aspectRatio` and hero `width: '100%'`.
- `trailing` goes in the tile row as a square tile (so '+' sits after tile n). With 0 photos and a trailing, the
  trailing tile is rendered alone (square, in the row); with 0 photos and no trailing → `null`.
- Each tile: `Pressable testID="photo-tile-i" accessibilityRole="imagebutton" accessibilityLabel="Photo i+1 of n"`,
  `expo-image` `Image source={{ uri: resolvePhotoUri(m.file_path) }} contentFit="cover"`, badge (`renderBadge(m, i)`)
  absolutely over the tile but as a **sibling** of the Pressable in a wrapper View (built in M2-03: an accessible
  imagebutton flattens its children, so a nested ✕ would be unreachable with VoiceOver). Measured tile width is
  floored to the pixel grid so three always fit; a non-button badge ('new') sets `pointerEvents="none"`. No `onPressPhoto` → tile not pressable (`disabled`).
- Staged drafts render through the same path: a draft's `file_path` is the picker's `file://` uri, which
  `resolvePhotoUri` passes through unchanged (`HAS_SCHEME`).
- M3 uses it on the detail screen (`onPressPhoto` opens the viewer, M4); M2 only uses it in edit.
- Export from `src/components/index.ts`.

## Staged adds (M2-05)

Draft type (in edit.tsx, not exported): `type StagedPhoto = NewPhoto & { key: string }` — `NewPhoto` from
`use-media-actions` (`Omit<Media,'file_path'> & { sourceUri }`); `key = asset.assetId ?? asset.uri`.

Flow:
1. '+' tile: `Pressable accessibilityRole="button" accessibilityLabel="Add photos"`, hidden when grid count ≥ 20
   (APP_SPECIFICATIONS: max 20 per spot). A `pickingRef` guard makes a double tap launch once.
2. `requestMediaLibraryPermissionsAsync()`; `granted === false` → `Alert.alert('Photo access needed', 'Allow photo
   access in Settings to add photos.')`, nothing staged.
3. `launchImageLibraryAsync({ mediaTypes: ['images'], allowsMultipleSelection: true, exif: true, quality: 0.8,
   selectionLimit: 20 - count })` (same options as `app/import/index.tsx`). Canceled → nothing.
4. Each asset → `importPhotoFromAsset(asset, nowIso)` (`src/utils/exif.ts`) → `captured_at` (EXIF DateTimeOriginal,
   DateTime, else now) and `location` (signed EXIF GPS or `undefined`); `id: newId()`, `spot_id: spot.id`,
   `sourceUri: asset.uri`, `created_at: nowIso`. Skip keys already staged (dedupe, M2-07).
5. Grid shows `[...visibleExisting, ...staged]`, staged with a 'new' mark; drafts render via `file_path: sourceUri`.
6. Dismiss/unmount: drafts are React state only → dropped; nothing copied, no row written.
7. Save, in order: `removePhotos(removedIds)` → `savePhotos(staged)` → primary → `updateSpot(patch)` → alert or back.
   - `savePhotos` changes to resolve the `Media[]` actually saved and uses `Promise.allSettled`, so one failed
     `persistPhoto`/`insertMedia` neither throws away the others nor skips `addMany` (test in
     `use-media-actions.test.ts`; Quick Add/import callers ignore the result, unchanged).
   - Primary: spot had no photos (`spotPhotos(spot, media).length === 0`) and ≥1 saved → `primary_photo_id = saved[0].id`;
     primary removed → first remaining existing, else `saved[0].id`, else `null`; otherwise not in the patch.
   - Fewer saved than staged → `Alert.alert("Some photos couldn't be added", …, [{ text: 'OK', onPress: back }])`,
     combined with the existing "couldn't be removed" alert path (one alert, back from its OK).

Built in M2-05 (after the Opus review): Save drops saved drafts and removed ids from state (and the grid hides any
draft already in the store), so the grid never shows a photo twice and a retry after a failed `updateSpot` writes
nothing again; Save caps the adds at `20 − (existing − removed)` so a failed removal can't make 21; '+' does nothing
while saving; the staged badge is a 'new' pill plus the same ✕ (unstage, announced 'New photo removed'). Mixed
failures share one alert, "Some photo changes didn't save".

How expo-image-picker is mocked: `jest.mock('expo-image-picker', () => ({ launchImageLibraryAsync: jest.fn(),
requestMediaLibraryPermissionsAsync: jest.fn() }))` — both names from
`node_modules/expo-image-picker/build/ImagePicker.d.ts` (lines 25, 96); results typed with `ImagePickerResult` /
`ImagePickerAsset` (`ImagePicker.types.d.ts`: `canceled`, `assets`, `assetId`, `uri`, `exif`). Permission fixture
`{ granted: true, status: 'granted', canAskAgain: true, expires: 'never' }`. Tests that render edit without mocking it
still load: jest-expo's native-module mock makes the un-mocked functions resolve `undefined` (probed 2026-10-21), and
edit only calls them on '+'. Fixture asset: `{ assetId: 'a1', uri: 'file:///picked/a1.jpg', width, height, exif: {
DateTimeOriginal: '2026:10:12 14:22:05', GPSLatitude: 40.7, GPSLatitudeRef: 'N', GPSLongitude: 74.0, GPSLongitudeRef:
'W' } }` → `captured_at '2026-10-12T14:22:05'`, `location { 40.7, -74 }`.

Tests `src/__tests__/edit-add-photos.test.tsx` (new), `use-media-actions` mocked as in edit-remove-photo:
1. press 'Add photos' → `launchImageLibraryAsync` called with `allowsMultipleSelection: true, exif: true`.
2. two assets → two new tiles with 'new' text; Save → `savePhotos` once with two entries, `spot_id` = spot id,
   `captured_at`/`location` from fixture EXIF; `updateSpot` patch has no `location` key.
3. unmount without Save → `savePhotos` never called.
4. spot with no photos + one add → patch `primary_photo_id` = that entry's id; spot with photos → no `primary_photo_id` key.
5. stage removal of an existing photo + add one → `removePhotos(['m1'])`, `savePhotos([new])`; hint '1 photo will be
   removed when you save.' visible with the 'new' tile.
6. permission `granted: false` → `Alert.alert` title 'Photo access needed'; picker not launched; no tile.
7. same asset returned by two picks (or double tap) → staged once.
8. `savePhotos` resolves fewer than staged → alert before `router.back()` (back only from OK).
9. canceled pick → nothing staged.
