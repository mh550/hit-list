## Older details (M3-02)

- State in the screen: `legacy: SpotLegacy | null` (initial `null`), `open = false`.
- `const db = useSQLiteContext()`. `useEffect(() => { let live = true; getSpotLegacy(db, id).then((l) => live &&
  setLegacy(l)).catch((e) => console.warn('Older details unreadable', id, e)); return () => { live = false }; },
  [db, id])` → **called once per mount**, not on store updates (deps are `db`, `id` only; spot/media are not deps).
  Bad JSON → one `console.warn` (not `error`: the suite must stay at zero `console.error`), `legacy` stays `null`,
  no disclosure, no crash.
- `rows = legacy ? formatLegacyDetails(legacy, units) : []`, `units` from `useSettingsStore((s) => s.units)`
  (switching units on Profile re-renders the rows without a re-fetch). `rows.length === 0` (null or all-empty
  archive) → nothing rendered, not even the header.
- Header: `Pressable accessibilityRole="button" accessibilityState={{ expanded: open }}`, text "Older details" +
  chevron (`chevron-forward` / `chevron-down`), small gray. **Collapsed by default**; tap toggles. Open → one row
  per entry: label (gray) left, value right, wraps. Read-only; edit/save never touch `legacy_json` (`updateSpot`
  has no such field).

### Answers to the M3-04 questions

1. **Is `getSpotLegacy` called once, not on every store update? Yes.** `OlderDetails`'s effect depends only on
   `[db, spotId]` (`units` is read outside it), and `key={spot.id}` remounts it if the id changes. Tested in
   `spot-detail.test.tsx`: "reads the archive once per mount with the db and the id, not on store updates" (it updates
   the store, rerenders, sees 'changed' and still counts 1 call), and "shows lengths in the units picked on Profile"
   (switching units keeps it at 1 call).
2. **Does unreadable `legacy_json` warn once and show no disclosure, without crashing? Yes.** `JSON.parse` runs inside
   the async `getSpotLegacy`, so bad JSON becomes a rejected promise. The screen's `.catch` calls `console.warn` once,
   `legacy` stays `null`, and `OlderDetails` renders nothing. Tested in `db-spots.test.ts` "rejects when the archive is
   not JSON…" (real node:sqlite, `SyntaxError`) and `spot-detail.test.tsx` "warns once and shows no disclosure when the
   archive cannot be read".
3. **Does VoiceOver read 'Skate stopped' as text, not a checkbox? Yes.** `Tag` (`src/components/Chip.tsx`) is a plain
   `View` + `Text`: no Pressable, no role, no state, not `accessible`. The red outline adds to the words; it is not the
   only signal. Tested in "reads the tags as text, not as checkboxes or buttons".
