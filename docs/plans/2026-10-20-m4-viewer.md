## Route (M4-03)

- File `app/spot/[id]/photos.tsx`; params `id`, `index` (string; `parseInt`, NaN → 0, clamp to `[0, n-1]`, so
  `'99'` on 7 photos opens at 6).
- `app/_layout.tsx`: `<Stack.Screen name="spot/[id]/photos" options={{ presentation: 'fullScreenModal', headerShown: false }} />`.
- Opened from detail: `PhotoGrid onPressPhoto={(i) => router.push({ pathname: '/spot/[id]/photos', params: { id, index: String(i) } })}`
  (test accepts that or `'/spot/<id>/photos?index=3'`; M4-03 picks the string form if the object form makes the
  assertion awkward). Tiles become role `imagebutton` (PhotoGrid already does this when `onPressPhoto` is set).
- Missing spot (`id` not in store) → centred 'Spot not found' (same as detail).
- Root `View` `flex: 1, backgroundColor: '#000'`; `<StatusBar hidden />` from `expo-status-bar` rendered inside the
  screen: expo-status-bar stacks props per mounted component, so unmounting restores the root's `style="dark"`
  bar (no manual restore).
- Chrome (absolute, over the pager, `useSafeAreaInsets` top): counter `"{page + 1} / {n}"` top-centre (white,
  `accessibilityRole="text"`, `accessibilityLiveRegion="polite"`); ✕ top-right: `Pressable accessibilityRole="button"
  accessibilityLabel="Close"`, `hitSlop` so the target is ≥ 44×44, `onPress → router.back()`.
- Back gesture / Android hardware back: no interception; the Stack pops the modal (spec §3.3 "Back gesture also
  closes"). `fullScreenModal` on iOS has no edge-swipe, so swipe-down + ✕ are the iOS exits.

## Pager choice: `FlatList` horizontal `pagingEnabled` + `getItemLayout`

Why: spec §10 lets the builder pick FlatList or `Animated.ScrollView`. FlatList gives virtualization (a spot may have
20 photos; `windowSize={3}`, `initialNumToRender={1}`, `maxToRenderPerBatch={1}`, `removeClippedSubviews` → at most
~3 decoded full-size images), `initialScrollIndex` (needs `getItemLayout`: `(_, i) => ({ length: width, offset:
width * i, index: i })` with `useWindowDimensions().width`; every page is exactly one window wide, so this is exact),
and `scrollEnabled` as a plain prop for the zoom lock. `Animated.ScrollView` would render all 20 pages and need manual
initial offset. RN's `FlatList` (not gesture-handler's): page gestures fail on horizontal movement at 1× (below), so
the native scroll view wins horizontal swipes without cross-wiring.

- `data`: the viewer's order (D29): ids snapshotted from `spotPhotos(spot, mediaBySpot[id])` on mount (`useState`
  initialiser), then each render maps them to current `Media` rows and drops removed ones. So 'Set as primary' does
  not jump the photo to page 1 under the user; the detail grid reorders (primary first) as usual.
- `keyExtractor` = media id; `showsHorizontalScrollIndicator={false}`.
- Page index state: `onMomentumScrollEnd` → `Math.round(contentOffset.x / width)`, clamped. Test fires
  `fireEvent(list, 'momentumScrollEnd', { nativeEvent: { contentOffset: { x: 5 * width, y: 0 } } })` → '6 / 7'.
- `scrollEnabled={pagingEnabled(scale)}` where `scale` is React state fed by the current page's `onScaleChange`
  (M4-04); reset to 1 on page change.
- Each page: `View` width × height, `accessibilityLabel="Photo N of M"`, `accessibilityHint="Double-tap and hold for
  options"` (M4-05), containing `ZoomablePhoto`.
- Image: `expo-image` `<Image source={{ uri: resolvePhotoUri(m.file_path) }} contentFit="contain" recyclingKey={m.id}
  style={StyleSheet.absoluteFill} />` (recyclingKey: recycled cells never flash the previous photo).

## Gesture composition (M4-04): `src/components/ZoomablePhoto.tsx`

Props: `{ uri: string; recyclingKey: string; width: number; height: number; onScaleChange?: (scale: number) => void;
onRequestClose?: () => void; onLongPress?: () => void; testIdPrefix?: string }`. Exported from
`src/components/index.ts`. Target < 150 lines excluding styles.

Shared values (reanimated): `scale`, `savedScale`, `tx`, `ty`, `savedTx`, `savedTy`, `dragY` (swipe-down offset at 1×).
Every number comes from `gallery-gestures.ts`; worklets read only shared values and props captured as plain numbers
(`width`, `height`), never React state. Pure functions are marked `'worklet'` so they run on the UI thread.

```ts
const pinch = Gesture.Pinch()
  .onUpdate((e) => { scale.value = clampScale(savedScale.value * e.scale); /* focalZoom → tx/ty */ })
  .onEnd(() => { savedScale.value = scale.value; clamp tx/ty via clampPan; scheduleOnRN(onScaleChange, scale.value) });
const pan = Gesture.Pan()            // rebuilt (useMemo on `zoomed` boolean state) so its config can change
  // at 1×: vertical only → the FlatList keeps horizontal swipes
  .activeOffsetY(zoomed ? undefined : [-10, 10]).failOffsetX(zoomed ? undefined : [-10, 10])
  .onUpdate((e) => zoomed ? (tx/ty = clampPan({ x: savedTx + e.translationX, y: … }, scale, viewport))
                          : (dragY.value = Math.max(0, e.translationY)))
  .onEnd((e) => { if (shouldClose(e.translationY, scale.value)) scheduleOnRN(onRequestClose); else dragY → withTiming(0);
                  savedTx/savedTy = tx/ty });
const doubleTap = Gesture.Tap().numberOfTaps(2)
  .onEnd((e) => { next = toggleZoom(scale.value); scale → withTiming(next); tx/ty → next === 1 ? 0 : clampPan(focalZoom(e, scale, next)); scheduleOnRN(onScaleChange, next) });
const longPress = Gesture.LongPress().minDuration(450).onStart(() => scheduleOnRN(onLongPress));
const composed = Gesture.Simultaneous(pinch, pan, Gesture.Exclusive(doubleTap, longPress));
```

- `scheduleOnRN` from `react-native-worklets` (reanimated 4's replacement for `runOnJS`; both exist in 4.5).
- `zoomed` (React state, `scale > 1.05` via `pagingEnabled`) is set through `onScaleChange` too; it only rebuilds
  the pan's activation offsets.
- Animated style: `transform: [{ translateX: tx }, { translateY: ty + dragY }, { scale }]`; backdrop opacity follows
  `dragY` (`1 - dragY / 400`, floor 0.4) as visual feedback for the swipe-down.
- Each gesture `.withTestId(\`${testIdPrefix}-pinch|pan|double-tap|long-press\`)` → tests use
  `fireGestureHandler(getByGestureTestId('viewer-pan-0'), [{ state: State.BEGAN }, { state: State.ACTIVE, translationY: 150 }, { state: State.END, translationY: 150 }])`
  (names from `node_modules/react-native-gesture-handler/lib/typescript/jestUtils/jestUtils.d.ts`:
  `fireGestureHandler`, `getByGestureTestId`). Proven in Jest by `root-layout.test.tsx`.
- Zoom lock test (M4-04 step 2): `screen.UNSAFE_getByType(ZoomablePhoto)` → `act(() => props.onScaleChange(2))` →
  FlatList `scrollEnabled` false; at 1× true.

## Pure functions: `src/utils/gallery-gestures.ts` (M4-02)

All `'worklet'`, no imports from React or reanimated. Constants exported: `MIN_SCALE = 1`, `MAX_SCALE = 4`,
`DOUBLE_TAP_SCALE = 2.5`, `ZOOMED_EPSILON = 1.05`, `CLOSE_DISTANCE = 120`.

```ts
type Point = { x: number; y: number };
type Size = { width: number; height: number };
clampScale(scale: number): number                              // [1, 4]
toggleZoom(scale: number): number                              // scale < 1.05 ? 2.5 : 1
clampPan(t: Point, scale: number, viewport: Size): Point       // |x| ≤ width*(scale-1)/2, |y| ≤ height*(scale-1)/2; scale ≤ 1 → {0,0}
pagingEnabled(scale: number): boolean                          // scale <= 1.05
shouldClose(dy: number, scale: number): boolean                // scale <= 1.05 && dy > 120
focalZoom(focal: Point, scale: number, nextScale: number, viewport: Size): Point
                                                               // translation keeping `focal` (view coords) fixed;
                                                               // focal at the centre → {0,0}
```

`clampPan` bounds use the viewport, not the image's contained size (spec values: scale 2 on 390×844 → ±195, ±422).
That lets a letterboxed photo pan its black bars into view when zoomed; accepted for now (simple, testable),
revisit on the phone. `focalZoom` takes `viewport` (for the centre) in addition to the feature text's
`(focal, scale, nextScale)`; M4-02 may give it a default if the test calls it with three arguments. `-0` results
are normalised to `0` so `toEqual({ x: 0, y: 0 })` holds.

## Long-press sheet (M4-05)

- `Alert.alert(title = 'Photo', undefined, [{ text: 'Set as primary', onPress }, { text: 'Remove photo', style:
  'destructive', onPress }, { text: 'Cancel', style: 'cancel' }])`. On iOS three buttons render as a vertical
  alert list, close enough to an action sheet. **No `ActionSheetIOS`, no new dependency.**
- Set as primary → `updateSpot(spotId, { primary_photo_id: media.id })` (`useSpotActions`); counter unchanged (D29
  keeps the order).
- Remove photo → `Alert.alert('Remove this photo?', 'It is taken off this spot.', [{ text: 'Cancel', style:
  'cancel' }, { text: 'Remove', style: 'destructive', onPress }])` (no camera-roll promise: Quick Add photos are
  never in the camera roll) →
  `removePhotos([media.id])` (`useMediaActions`; resolves the ids removed). If that photo was the spot's primary
  (`spot.primary_photo_id === id`, or no explicit primary and it was `primaryPhoto`), `updateSpot(spotId, {
  primary_photo_id: <the photo now shown in its place, i.e. next in viewer order, else previous> ?? null })`.
  Remaining 0 → `router.back()`. Page index clamps to the new last page; counter 'N / 6'.
- The page's `onLongPress` comes from the long-press gesture; the hint text tells VoiceOver users to double-tap and
  hold, which iOS passes through as a long press.
