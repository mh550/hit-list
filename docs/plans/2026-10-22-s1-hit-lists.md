# S1 plan: hit lists, local (no accounts)

Spec: `docs/specs/2026-10-22-accounts-and-sharing.md` §1 (vocabulary), D33 (the word), D49 (tabs), §5.1 (Lists tab),
§5.2 (getting spots into lists), §7 S1. Features: S1-01 this plan · S1-02 migration 4 + DB · S1-03 store + hook +
launch load · S1-04 SpotsBrowser extraction · S1-05 Lists tab · S1-06 list screen · S1-07 detail 'In lists' + sheet ·
S1-08 multi-select · S1-09 list picker · S1-10 walkthrough · S1-11 review. Every build feature: RED test first
(watch it fail), then code; `check.sh` green per commit. Diff base for the review: `4aa5326`.

Starting point: schema v3 (3 migrations), 54 suites / 656 tests. The Spots tab (`app/(tabs)/index.tsx`, 299 lines)
holds the whole List | Map body; tabs are Spots · Profile. Soft-deleted spots never reach the store
(`getSpots` skips them, `removeSpot` filters them out), but every list selector still checks `deleted_at` so a stale
row can't count.

## Decisions taken in this plan

- **Area columns ship in migration 4, unused until S2.** `kind`, `area_center_lat/lng`, `area_radius_m`,
  `area_filters_json`, `area_place` exist from v4 so S2 adds **no** migration (the plan's reserved numbers stay:
  5 = sync, 6 = profiles, 7 = send columns, 8 = members). S1 writes `kind = 'manual'` and NULL area columns only.
- **`owner_id` / `added_by` are nullable and stay NULL in S1** (no accounts). S5's adoption (D38) fills them.
- **`sync_queue` (migration 1) is left alone** until S5's migration drops it with `SyncQueueItem`. Migration 4 neither
  reads nor touches it.
- **`member_count` is not a column.** It is an optional field on `HitList`, always undefined in S1; S8 computes it
  from `hit_list_members`.
- **Deleting a list is a soft delete** (`deleted_at`); its `hit_list_spots` rows stay (S5 sync needs the tombstone,
  and nothing reads rows of a deleted list: `getListMemberships` joins on live lists). **Never deletes a spot.**
- **Soft-deleting a spot leaves its `hit_list_spots` rows**; the selectors hide it. A hard spot delete (none in the
  app today) cascades the rows (`ON DELETE CASCADE`, foreign keys ON after `migrateDb`).
- **Lists show in name order** everywhere (Lists tab, sheet, picker): `selectListsByName`, `Intl.Collator`,
  case-insensitive, ties by `created_at`. `getHitLists` returns `ORDER BY created_at` (stable, no collation in SQL).
- **D52 *default*: one set of filters, search, sort and List | Map** (the `useSpotsStore` fields) is shared by the
  Spots tab, every list screen and the list picker. A filter set on a list screen is still on when you go back to the
  Spots tab (the Filter button's count shows it). Recorded in the spec §2 and asked in §9 Q13.
- **The picker's choice (`activeListId`) is not persisted**: every launch opens on 'My spots'.

## Types (`src/types/index.ts`, S1-02)

```ts
export type HitListKind = 'manual' | 'area';

export interface HitList {
  id: string;
  name: string;
  kind: HitListKind;              // 'manual' in S1; 'area' from S2
  owner_id?: string;              // undefined until accounts (S5)
  shared: boolean;                // false in S1; S8
  member_count?: number;          // computed in S8, never stored

  area_radius_m?: number;         // S2, whole metres like batch_import_radius
  area_filters?: SpotFilters;     // S2, area_filters_json
  area_place?: string;            // S2, "Capitol Hill"
  created_at: string;             // ISO 8601
  updated_at: string;             // ISO 8601
  deleted_at?: string;            // ISO 8601
}

export interface HitListSpot {
  list_id: string;
  spot_id: string;
  added_by?: string;              // undefined until accounts
  added_at: string;               // ISO 8601

/** A patch for a list; undefined keeps the stored value (S2 adds the area fields). */
export type HitListUpdate = Partial<Pick<HitList, 'name' | 'shared' | 'updated_at'>>;
```

## Migration 4 (`src/db/schema.ts`, S1-02)

Appended as `migration4`; `MIGRATIONS = [migration1, migration2, migration3, migration4]`, `LATEST_SCHEMA_VERSION`
4. Runs in `migrateDb`'s per-migration transaction with its `user_version = 4` bump; foreign keys are OFF while it runs
and ON after. `IF NOT EXISTS` everywhere, like migration 1, so a half-applied state from a crashed launch can't wedge
the upgrade (a DB from a newer build has `user_version` > 4 and is never touched). Migrations 1–3 stay
byte-for-byte unchanged.

```sql
CREATE TABLE IF NOT EXISTS hit_lists (
  id TEXT PRIMARY KEY NOT NULL,
  owner_id TEXT,
  name TEXT NOT NULL,
  kind TEXT NOT NULL DEFAULT 'manual',
  area_center_lat REAL,
  area_center_lng REAL,
  area_radius_m INTEGER,
  area_filters_json TEXT,
  area_place TEXT,
  shared INTEGER NOT NULL DEFAULT 0,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,
  deleted_at TEXT
);
CREATE TABLE IF NOT EXISTS hit_list_spots (
  list_id TEXT NOT NULL REFERENCES hit_lists(id) ON DELETE CASCADE,
  spot_id TEXT NOT NULL REFERENCES spots(id) ON DELETE CASCADE,
  added_by TEXT,
  added_at TEXT NOT NULL,
  PRIMARY KEY (list_id, spot_id)
);
CREATE INDEX IF NOT EXISTS idx_hit_lists_deleted_at ON hit_lists(deleted_at);
CREATE INDEX IF NOT EXISTS idx_hit_list_spots_spot_id ON hit_list_spots(spot_id);
```

No SQLite defaults on timestamps (the app writes ISO 8601, CLAUDE.md "Timestamps"). The primary key covers lookups by
`list_id`; the second index covers the cascade from `spots` and "which lists is this spot in".

## DB API (`src/db/hit-lists.ts`, re-exported from `src/db/index.ts`, S1-02)

Same pattern as `spots.ts`: an explicit `HIT_LIST_COLUMNS`, a `HitListRow` interface, `rowToHitList` (NULL →
undefined, `shared` 0/1 → boolean, `area_center` only when both lat and lng are non-NULL, `area_filters_json` parsed
with a `console.warn` + undefined on unreadable JSON, never throws).

| Function | Signature | SQL / rule |
|---|---|---|
| `insertHitList` | `(db, list: HitList) => Promise<void>` | one INSERT of every column |
| `getHitLists` | `(db) => Promise<HitList[]>` | live only (`deleted_at IS NULL`), `ORDER BY created_at` |
| `updateHitList` | `(db, id, updates: HitListUpdate) => Promise<void>` | only defined keys; `updated_at` defaults to now; live rows only |
| `softDeleteHitList` | `(db, id, at: string) => Promise<void>` | `deleted_at = at, updated_at = at` |
| `addSpotsToList` | `(db, listId, spotIds: string[], addedAt: string) => Promise<void>` | `INSERT OR IGNORE` per id inside `withTransactionAsync` (idempotent; a second add keeps the first `added_at`); `[]` is a no-op |
| `removeSpotFromList` | `(db, listId, spotId) => Promise<void>` | `DELETE` one row |
| `getListMemberships` | `(db) => Promise<Record<string, string[]>>` | `SELECT s.spot_id, s.list_id FROM hit_list_spots s JOIN hit_lists l ON l.id = s.list_id WHERE l.deleted_at IS NULL ORDER BY s.added_at`; `{ [spotId]: listId[] }` |

`src/__tests__/factories.ts` gains `createTestHitList(overrides)` (id `newId()`, name 'Downtown', kind 'manual',
shared false, fixed ISO timestamps like `createTestSpot`).

## Store (`src/stores/hit-lists-store.ts`, exported from `src/stores/index.ts`, S1-03)

```ts
interface HitListsState {
  lists: HitList[];                               // live lists only
  membershipBySpot: Record<string, string[]>;     // spotId → listIds
  activeListId: string | null;                    // the Spots tab's list picker; null = 'My spots'

  setLists: (lists: HitList[]) => void;
  setMemberships: (m: Record<string, string[]>) => void;
  addList: (list: HitList) => void;
  updateList: (id: string, updates: HitListUpdate) => void;
  removeList: (id: string) => void;               // also resets activeListId to null when it was this list
  addMemberships: (listId: string, spotIds: string[]) => void;    // no duplicates
  removeMemberships: (listId: string, spotIds: string[]) => void; // drops empty keys
  setActiveListId: (id: string | null) => void;
}
```

Selectors (pure, exported; screens select the raw state and `useMemo` the result, never a selector that builds an
array inside `useStore`, which loops under zustand 5):

- `selectListSpots(list: HitList, spots: Spot[], membershipBySpot) => Spot[]`: spots with `deleted_at === undefined`
  whose id maps to `list.id`, in `spots` order.
- `selectSpotLists(spotId, lists, membershipBySpot) => HitList[]`: the live lists the spot is in, name order.
- `selectListCounts(lists, spots, membershipBySpot) => Record<string, number>`: live spots per list (every list
  present, 0 when empty).
- `selectListsByName(lists) => HitList[]`: name order (above).

## Hook (`src/hooks/use-hit-list-actions.ts`, S1-03)

`useHitListActions()` → `{ createList, renameList, deleteList, addSpotsToList, removeSpotFromList }`, each a
`useCallback` on `useSQLiteContext()`. Pattern of `useSpotActions.updateSpot`: store first, then the DB; on a DB
rejection `console.error('[useHitListActions] <fn> failed:', err)`, revert the store, rethrow.

| Action | Store first | DB | Revert |
|---|---|---|---|
| `createList(name) => Promise<HitList>` | `addList({ id: newId(), name: name.trim(), kind: 'manual', shared: false, created_at = updated_at = now })` | `insertHitList` | `removeList(id)` |
| `renameList(id, name)` | `updateList(id, { name, updated_at })` (one stamp) | `updateHitList` | `updateList(id, before)` (name + updated_at) |
| `deleteList(id)` | `removeList(id)` | `softDeleteHitList(db, id, now)` | `addList(before)` (+ restore `activeListId` if it was this list) |
| `addSpotsToList(listId, spotIds)` | `addMemberships` | `addSpotsToList(db, …, now)` | `removeMemberships` of the ids that were **not** already in it |
| `removeSpotFromList(listId, spotId)` | `removeMemberships(listId, [spotId])` | `removeSpotFromList` | `addMemberships(listId, [spotId])` (only if it was in) |

`useDbInit` (S1-03) loads, after spots and media and before settings, `setLists(await getHitLists(db))` and
`setMemberships(await getListMemberships(db))`, each in its own `try/catch` logging
`[useDbInit] Failed to initialize database (hit lists|memberships):`; `isReady` still becomes true.
