# S2 plan: area picker and area lists, local

Spec: `docs/specs/2026-10-22-accounts-and-sharing.md` §1 (Area list), D41 (one picker, two uses), §5.1, §5.3, §7 S2.
Features: S2-01 this plan · S2-02 geometry + store · S2-03 picker screen · S2-04 saving, Lists tab, list screen,
sheet, detail · S2-05 walkthrough · S2-06 review. Every build feature: RED test first (watch it fail), then code;
`check.sh` green per commit. **Diff base for the review: `2488824`** (HARNESS: S1 verified).

Starting point: schema v4 (migration 4 already has the area columns: `kind`, `area_center_lat/lng`, `area_radius_m`,
`area_filters_json`, `area_place`), 814 tests. `rowToHitList`/`insertHitList` already read and write every area
column; `updateHitList` writes only `name`/`shared`. **S2 adds no migration.** No new dependency: geocoding is
`expo-location`'s `geocodeAsync`, the circle is react-native-maps' `Circle`.

*Done when (spec):* saving a spot inside an area list's circle makes it appear in that list with no other action.

## Decisions taken in this plan

- **An area list's spots are computed, never stored.** `kind = 'area'`, `area_*` columns set, **no `hit_list_spots`
  rows**. Its spots = the rider's live spots inside the circle that pass `area_filters`. A spot saved, moved or
  re-tagged later joins or leaves on the next render. Nothing writes memberships for it, so no sync work in S5.
- **One source of truth for "in the area":** `selectAreaSpots` (store, below). The picker's count, `selectListSpots`,
  `selectListCounts`, `selectSpotLists` and the Add-to-list sheet all call it. It uses `spotsInCircle` from
  `src/utils/area.ts` for the geometry.
- **'Just these N' is a plain manual list.** `createList(name, { kind: 'manual' })` + `addSpotsToList(id, ids)`.
- **D53 *default*: an area list ignores spots with no location** (`NO_LOCATION`, `(0, 0)`). They are never inside any
  circle, and the picker's count leaves them out.
- **D54 *default*: the place name** is the trimmed text the rider searched for, as typed ('Capitol Hill'), or
  'my location' after 'Use my location' (or when the picker opened on the current fix). No reverse geocoding. If the
  rider drags the centre more than a quarter of the radius away from where the place put it, the place is dropped
  (`keepsPlace`), and the label becomes 'Area · 2 mi'.
- **D55 *default*: the picker's filters are the shared filters (D52).** The picker uses the one `useSpotsStore.filters`
  through the existing `FilterSheet`. 'Keep it updated' saves a copy as `area_filters`. 'Edit area' loads the
  list's `area_filters` into the shared filters when it opens (the Filter badge shows it), and 'Save area' writes the
  filters set at that point. Closing the picker (Save or Cancel) puts the rider's own filters back (S2-06 review, m2). The Spots tab's text search (`searchQuery`) is **not** applied in the picker and never
  saved. On the area list's own screen, `SpotsBrowser` applies the shared filters and search on top, as on any list.
- **D56 *default*: radius.** Default 2 mi (imperial) / 2 km (metric) = `nearestStep(3219, units)`. A saved radius is
  whole metres, always a `RADIUS_STEPS_M` value of the unit it was picked in. If the rider later switches units, the
  saved radius stays as it was: the label converts it ('Area · 3.2 km'), and the picker selects no chip until one is
  tapped. Nothing is silently resized.
- **The picker's start centre is fixed once, on mount.** It is the current fix if known, otherwise the centre of
  `initialRegion(spots, null)` (every located spot), otherwise `DEFAULT_REGION` (Seattle). A fix that arrives later
  only enables 'Use my location'; the map does not jump.
- **A map region change never geocodes.** Only submitting the search field calls `geocodeAsync`.
  `onRegionChangeComplete` only sets `center` (and maybe drops the place).
- **Geocoding is Apple's network service** (CLGeocoder via expo-location, like the town backfill). The typed text goes
  to Apple, and nothing else does. A rejection or `[]` shows 'No place found' with no `console.error`.
- **'Send these N spots' is added to the picker's bottom bar in S7** (D41). S2's bar has 'Save as hit list' only.
- **For S8 (noted, not built):** with others' spots on the phone (D47), `selectAreaSpots` must keep only spots owned
  by the list's owner (`spot.owner_id === list.owner_id`; both undefined = local). S2 has no owners, so every spot
  counts.

## Geometry (`src/utils/area.ts`, S2-02)

Pure. Imports `haversineDistance`/`isKnownLocation` from `geo.ts`, `UnitSystem`/`GeoPoint`/`Spot` types, and `Region`
(type only) from `react-native-maps`, as `map-region.ts` does.

```ts
const METERS_PER_MILE = 1609.344;

/** The radius chips, in whole metres, per unit (D56). */
export const RADIUS_STEPS_M: Record<UnitSystem, readonly number[]> = {
  imperial: [402, 805, 1609, 3219, 8047, 16093, 40234], // 0.25, 0.5, 1, 2, 5, 10, 25 mi (Math.round(mi × 1609.344))
  metric: [500, 1000, 2000, 5000, 10000, 25000, 50000], // 0.5, 1, 2, 5, 10, 25, 50 km
};
export const DEFAULT_AREA_RADIUS_M = 3219; // 2 mi; metric riders get nearestStep(3219, metric) = 2000

/** Spots with a known location whose haversine distance to `center` is ≤ radiusM (the boundary counts), input order. */
export function spotsInCircle(spots: Spot[], center: GeoPoint, radiusM: number): Spot[];

/** The step of `units` closest to radiusM (ties go to the smaller one). */
export function nearestStep(radiusM: number, units: UnitSystem): number;

/** '0.25 mi', '2 mi', '3.2 km': below 1 unit two decimals, otherwise one, trailing zeros dropped. */
export function radiusLabel(radiusM: number, units: UnitSystem): string;

/** 'Area · 2 mi' / 'Area · 2 mi of Capitol Hill' (place trimmed; blank = none). */
export function areaLabel(radiusM: number, units: UnitSystem, place?: string): string;

/** A camera region centred on `center` whose span holds the whole circle with a 1.3× margin. */
export function circleRegion(center: GeoPoint, radiusM: number): Region;

/** D54: the place still describes `center` when it is within a quarter of the radius of where the place put it. */
export function keepsPlace(placeCenter: GeoPoint, center: GeoPoint, radiusM: number): boolean;
```

- `circleRegion`: `latitudeDelta = 2 · radiusM / 111_320 · 1.3`; `longitudeDelta = latitudeDelta / cos(lat)` with
  `cos` floored at 0.01 (near the poles); clamped to 180 / 360 like `map-region.ts`. For 1609 m at 47.6°:
  latΔ ≈ 0.0376 (≥ the circle's 0.0289), lngΔ ≈ 0.0557 (≥ 0.0428).
- The chip labels are `radiusLabel(step, units)`: 0.25 mi … 25 mi, 0.5 km … 50 km.

## Area lists (store, types, DB, hook; S2-02 and S2-04)

**Types** (`src/types/index.ts`): `HitListUpdate` gains the area fields. `null` clears the place, as in `SpotUpdate`.

```ts
export type HitListUpdate = Partial<Pick<HitList, 'name' | 'shared' | 'updated_at' | 'area_center' | 'area_radius_m' | 'area_filters'>> & {
  area_place?: string | null;
};
/** What createList needs beyond the name. */
export type NewHitList =
  | { kind: 'manual' }
  | { kind: 'area'; area_center: GeoPoint; area_radius_m: number; area_place?: string; area_filters: SpotFilters };
```

**DB** (`src/db/hit-lists.ts`, S2-02): `updateHitList` also writes `area_center_lat/lng` (both from `area_center`),
`area_radius_m`, `area_filters_json` (JSON) and `area_place` (`null` → NULL), only for the keys given. Insert and read
already handle the area columns.

**Store** (`src/stores/hit-lists-store.ts`, S2-02):

```ts
/** The one rule for "in the area" (picker count, area lists, detail, sheet): live, located, inside, passes filters. */
export function selectAreaSpots(spots: Spot[], center: GeoPoint, radiusM: number, filters: SpotFilters): Spot[] {
  return selectFilteredSpots(spotsInCircle(spots.filter((s) => s.deleted_at === undefined), center, radiusM), filters);
}
```

- `selectListSpots(list, spots, membershipBySpot)`: a `kind 'area'` list with `area_center` and `area_radius_m` returns
  `selectAreaSpots(spots, center, radius, list.area_filters ?? DEFAULT_FILTERS)`. An area list missing either value
  returns `[]`. A manual list works as in S1.
- `selectListCounts`: an area list's count is `selectListSpots(list, …).length`. Manual lists keep the one-pass count.
- `selectSpotLists(spot: Spot, lists, membershipBySpot)`: **the first parameter changes from `spotId` to the spot**
  (the only caller is detail). An area list is included when `selectListSpots(list, [spot], {})` has the spot.
- `updateList(id, updates)`: `area_place: null` → `area_place` undefined. Other keys as today.

**Hook** (`src/hooks/use-hit-list-actions.ts`, S2-04):

- `createList(name, opts: NewHitList = { kind: 'manual' })`: the list gets `kind` and, for 'area', the four area
  fields. Store first, then the DB, revert on failure, as today. Existing callers (`createList(name)`) are unchanged.
- `updateHitList(id, updates: HitListUpdate)` (new, named after the DB function that it wraps): one `updated_at`
  stamp; store first, then `updateHitList(db, …)`; on failure `console.error`, the store goes back to the
  pre-update values of the keys that were patched, and the promise rejects. 'Save area' uses it. `renameList` stays.

## Picker screen (`app/area/index.tsx`, S2-03 and S2-04)

`app/_layout.tsx`: `<Stack.Screen name="area/index" options={{ presentation: 'fullScreenModal', title: 'Pick an area' }} />`.
The header has 'Cancel' on the left (`HeaderTextButton`, `router.back()`) and 'Filter' on the right (`HeaderTextButton`,
with the active filter count as in `SpotsBrowser`) → `FilterSheet`. Query params: `listId?` (edit mode).

State: `center: GeoPoint`, `radiusM: number`, `place?: string`, `placeCenter?: GeoPoint` (where the place put
the centre), `searchText`, `notFound: boolean`, `chooser: 'closed' | 'choose' | 'manual' | 'area'`.
`useCurrentLocation()` runs as on the Spots tab.

Layout, top to bottom:
1. **Search row:** `TextInput` (placeholder 'Search a place', accessibilityLabel 'Search a place',
   `returnKeyType 'search'`) + 'Use my location' button (accessibilityLabel 'Use my location', disabled while
   `currentLocation` is null). A 'No place found' line under it while `notFound` (cleared on the next edit or search).
2. **Map:** plain `MapView` (`ref`, `initialRegion = circleRegion(start, radius)`, `onRegionChangeComplete`), a
   `Circle` (`center`, `radius = radiusM`, translucent `colors.primary` fill + stroke), and one `Marker` per spot
   in the circle (`selectAreaSpots` result, pin colour `colors.primary`). Over it, a fixed centre pin
   (`pointerEvents="none"`, absolutely centred, `testID 'area-center-pin'`, a dot + stem View drawn in
   `colors.primary`; no new icon mapping).
3. **Radius chips:** a horizontal `ScrollView` of `Chip`s with `role 'radio'` (`Chip`'s role union gains
   `'radio'`, state `{ checked: selected }` like 'checkbox'), labels `radiusLabel(step, units)`,
   selected when `step === radiusM`. A tap sets `radiusM` and `animateToRegion(circleRegion(center, step))`.
4. **Bottom bar:** the count `spotCountLabel(n)` ('1 spot' / '23 spots', accessibilityLiveRegion polite; the helper
   moves from `app/(tabs)/lists.tsx` to `src/utils/spot-name.ts` so both use it), then
   'Save as hit list' (new mode) or 'Save area' (edit mode). Disabled at 0 spots in new mode? **No**: an empty area
   list is valid (spots come later); 'Just these 0 spots' is hidden when n = 0.

Behaviour:
- `n = selectAreaSpots(spots, center, radiusM, filters).length` in a `useMemo` (raw store reads, no array built
  inside `useStore`).
- `onRegionChangeComplete(region)` → `center = { latitude, longitude }`; if `place` is set and
  `!keepsPlace(placeCenter, center, radiusM)`, drop `place`. Never geocodes.
- Search submit: trimmed text empty → nothing. Otherwise `geocodeAsync(text)`. `[0]` → `center`, `place = text`,
  `placeCenter = center`, `animateToRegion(circleRegion(…))`. `[]` or a rejection → `notFound = true`. Results that
  arrive after another submit are ignored (a request counter).
- 'Use my location' → `center = currentLocation`, `place = 'my location'`, `animateToRegion`.
- **New mode:** 'Save as hit list' → a chooser card (transparent fade `Modal`, like `NameListSheet`) with
  - 'Just these N spots' (accessibilityLabel the same, hint text under it 'A normal hit list of the spots inside
    the circle right now'), hidden when N = 0;
  - 'Keep it updated' (hint 'An area list: your spots inside this circle, now and later');
  - 'Cancel'.
  S2-03: either option only closes the chooser. S2-04: either option → `NameListSheet` (title 'New hit list', confirm
  'Create'). Create → 'Just these' `createList(name, { kind: 'manual' })` then `addSpotsToList(id, ids)` (ids of
  `selectAreaSpots` at that moment); 'Keep it updated' `createList(name, { kind: 'area', area_center: center,
  area_radius_m: radiusM, area_place: place, area_filters: filters })` and no `addSpotsToList`. Then
  `router.replace('/list/<id>')`. On a rejection: `Alert.alert("Couldn't save the list", 'Please try again.')` and
  the sheet stays open.
- **Edit mode (`listId`):** the list from the store. If it is missing or not `kind 'area'`, show `EmptyState`
  'This list is gone' / 'It may have been deleted.' instead of the map. Otherwise, on mount:
  `center = area_center`, `radiusM = area_radius_m`, `place = placeCenter = …`, and
  `setFilters(area_filters ?? DEFAULT_FILTERS)` (D55). The single bottom action 'Save area' →
  `updateHitList(id, { area_center: center, area_radius_m: radiusM, area_place: place ?? null,
  area_filters: filters })` → `router.back()`. On failure, the same Alert.

## Risks to watch

- `router.replace('/list/<id>')` from a `fullScreenModal`: on the phone the list should replace the modal (card
  presentation). S2-05's walkthrough must call it out. If it animates oddly, fall back to `router.back()` then
  `router.push`.
- `onRegionChangeComplete` also fires after `animateToRegion` (search, chip, my location). That is harmless: it sets
  the same centre, and `keepsPlace` holds because the centre is the place's own.
- iOS `MKMapView` region deltas: `circleRegion` clamps them, as `map-region.ts` does.
- The detail's `selectSpotLists` signature change: one caller, plus the store tests' call sites.
- Many markers: the picker draws pins only for spots inside the circle. If a 25 mi circle holds hundreds, S2-06
  decides whether to cap them.

1. **The count never includes NO_LOCATION spots: yes.** `spotsInCircle` keeps only `isKnownLocation` spots
   (`src/utils/area.ts`). The picker count, the markers and every area-list selector go through `selectAreaSpots` → `spotsInCircle`.
2. **The stored radius is always a `RADIUS_STEPS_M` value in whole metres: yes.** A new list starts at
   `nearestStep(DEFAULT_AREA_RADIUS_M, units)` or takes a chip value. An edit keeps the saved radius until a chip is

   function with the list's `area_filters`. Both save paths store the `{ ...filters }` the count used.
4. **A geocodeAsync rejection shows 'No place found' and never a console.error: yes.** `search` catches it and
   treats it as `[]`, then `setNotFound(true)`. Nothing logs, and a stale rejection returns silently.
5. **A map region change never re-runs geocoding: yes.** `onRegionChangeComplete` only cancels an in-flight search on a
   gesture, sets `center` and may drop the place. `geocodeAsync` is called only from `search`, which is wired only to
