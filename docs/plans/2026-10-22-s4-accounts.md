# S4 plan: accounts in the app (email code, username, Profile, delete account)

> **For agentic workers:** one harness session per feature (S4-02 … S4-08); each build feature commits its test file
> **RED first** (`S4-0n: RED …`, first run fails, note the failure in the message), then the code that makes it pass.

**Goal:** a rider can sign in with an emailed 6-digit code, pick an @username, see their account on Profile, sign out
and delete the account; with no Supabase values in the build the app is exactly today's signed-out app.

**Architecture:** one lazily built supabase-js client (`src/sync/client.ts`) whose session lives in SecureStore (small)
or AES-GCM-encrypted in AsyncStorage with the key in SecureStore (large, D61); a zustand auth store mirrored from
`onAuthStateChange` by `useAuthInit`; three `app/auth/*` screens; one Deno Edge Function `account-delete`. Unit tests
use a hand-written fake client; the real thing is tested by `npm run test:integration` against the local stack.

**Tech stack:** `@supabase/supabase-js` 2.118.0 (auth-js, postgrest-js, functions-js 2.118.0), `expo-secure-store`
~57.0.4, `@react-native-async-storage/async-storage` 2.2.0, `expo-crypto` ~57.0.4 (already a dependency; its AES),
local Supabase CLI 2.121.0 (S3).

**Spec:** `docs/specs/2026-10-22-accounts-and-sharing.md` §3.1, §3.4 (fakes), §5.6, §6, §7 S4, D36–D39, D51, D58,
D61–D63. **Diff base for the S4-08 review: `166a7f3`** (HARNESS: S3 verified).

## Global constraints

- Unconfigured = signed-out only: either `EXPO_PUBLIC_SUPABASE_URL` or `EXPO_PUBLIC_SUPABASE_ANON_KEY` empty →
  `getSupabase()` is `null`, Profile says `Accounts aren't set up in this build`, nothing else changes (§3.1).
- No key or URL in any tracked file; `.env.example` holds empty values (done in S4-01). Integration keys come from
  `npx supabase status -o json` at run time only.
- Read env with the **dot form** `process.env.EXPO_PUBLIC_SUPABASE_URL` (Expo inlines only that form in Metro builds;
  Jest's babel-jest does not inline, so tests set `process.env` and use `jest.isolateModules`).
- Never `await` a supabase call inside an `onAuthStateChange` callback (auth-js documents a deadlock,
  `GoTrueClient.d.ts` ~l.100): the callback is synchronous and defers work with `setTimeout(…, 0)`.
- UI shows `error.message` strings or fixed copy, never a whole error object.
- Usernames per D39: 3–20 chars, `a–z 0–9 _ .`, unique case-insensitively (server: `citext` unique + check, S3); display
  name ≤ 50 (D58), optional (D63).
- Zero `console.error` in Jest; `npx expo lint && npx tsc --noEmit && npx jest --silent` green after every feature.

## Session storage (S4-02) — `src/sync/session-storage.ts`, D61 *default*

Supabase's documented LargeSecureStore pattern on expo-crypto's AES. Exports `sessionStorage: { getItem(key):
Promise<string|null>, setItem(key, value): Promise<void>, removeItem(key): Promise<void> }` (auth-js `SupportedStorage`).

- `setItem`: UTF-8 byte length (`TextEncoder`) ≤ **2048** → `SecureStore.setItemAsync(key, value)` and
  `AsyncStorage.removeItem(key)`. Larger → `AESEncryptionKey.generate()` (256-bit), `aesEncryptAsync(bytes, aesKey)`
  (pass a `Uint8Array`: a string input must be base64), `AsyncStorage.setItem(key, await sealed.combined('base64'))`,
  `SecureStore.setItemAsync(key, 'aes256gcm:' + await aesKey.encoded('base64'))`. A fresh key every write.
- `getItem`: SecureStore value `null` → `null`. Not prefixed → it is the value. Prefixed → read AsyncStorage,
  `AESSealedData.fromCombined(b64)`, `aesDecryptAsync(sealed, await AESEncryptionKey.import(keyB64, 'base64'))` → bytes
  → `TextDecoder`. Ciphertext missing (reinstall: the iOS keychain outlives the app, AsyncStorage does not) or decrypt
  throws → `removeItem(key)`, return `null` (= signed out), never throw.
- `removeItem`: both stores. Sign-out goes through auth-js `removeItem`, so the AES key leaves with the session.
- *As built (S4-02):* every operation on a key runs after the previous one (a per-key promise queue), so overlapping
  writes or a read between a write's two steps never pair one key with another write's ciphertext. A keychain or
  AsyncStorage **read** error returns `null` without deleting anything (only a missing ciphertext or a failed decrypt
  deletes). Known gap for S4-08: a session ≤ 2048 bytes sits in the keychain in plain form and survives an app
  delete + reinstall (the rider comes back signed in); a large one reads as signed out.
- SecureStore options: `{ keychainAccessible: SecureStore.AFTER_FIRST_UNLOCK }` so a background refresh can read it.
- Jest: `expo-secure-store` mocked in `jest.setup.ts` as an in-memory Map with `getItemAsync`/`setItemAsync`/
  `deleteItemAsync` (`node_modules/expo-secure-store/build/SecureStore.d.ts` l.99–123) + `AFTER_FIRST_UNLOCK`;
  async-storage via its shipped `@react-native-async-storage/async-storage/jest/async-storage-mock`; the existing
  expo-crypto mock gains `AESEncryptionKey` (`generate`, `import(str, 'base64')`, `encoded('base64')`), `AESSealedData`
  (`fromCombined`, `combined('base64')`), `aesEncryptAsync`, `aesDecryptAsync` backed by Node `aes-256-gcm` (12-byte IV,
  16-byte tag, combined = iv‖ciphertext‖tag), names from `node_modules/expo-crypto/build/aes/ExpoCryptoAES.d.ts`.

## Auth store and hook (S4-02)

`src/stores/auth-store.ts`:
```ts
export type AuthStatus = 'unconfigured' | 'signed_out' | 'signed_in' | 'needs_username';
interface AuthSnapshot { status: AuthStatus; userId: string | null; email: string | null;
  username: string | null; displayName: string | null }
// state = AuthSnapshot + setAuth(s: AuthSnapshot): void + setProfile(username: string, displayName: string | null): void
```
Initial `{ status: 'signed_out', all null }`.

`src/sync/auth.ts`: `resolveAuthState(client: SupabaseClient, session: Session | null): Promise<AuthSnapshot>` —
`null` session → `signed_out`; else `from('profiles').select('username, display_name').eq('id', user.id)
.maybeSingle()`: row with username → `signed_in`; row with `username` null → `needs_username`; **error or no row →
`signed_in` with username null** (offline launch never traps the rider on the username screen; refetched on the next
AppState `active`).

`src/hooks/use-auth-init.ts` `useAuthInit(): void`: no client → `setAuth({ status: 'unconfigured', … })`. Else
`getSession()` → `resolveAuthState` → `setAuth`; `onAuthStateChange((event, session) => { setTimeout(() => …) })` for
`SIGNED_IN`, `SIGNED_OUT`, `USER_UPDATED`, and `TOKEN_REFRESHED` only when its user is not the store's `userId`
(`INITIAL_SESSION` ignored: it repeats `getSession`); unsubscribes `data.subscription.unsubscribe()` on unmount.
*As built (S4-02):* every change takes a ticket when it happens, a fetch finishing after a newer change is dropped.
`getSession` answering an `isAuthRetryableFetchError` (offline, access token expired; auth-js keeps the stored session,
`GoTrueClient.js` `__loadSession`) leaves the store as it is; the refresh ticker (always on in RN,
`_handleVisibilityChange`) emits `TOKEN_REFRESHED` once online, which brings the account in. AppState `active` with
`signed_in` and no username refetches the profile. Mounted in `app/_layout.tsx` inside `DBInitializer`, as a small
`<AuthInit />` component next to the Stack.

## Delete account (S4-05 UI, function below; S4-06 runs it)

Profile's `Delete account` (D51): `Alert.alert('Delete your account?', 'Your spots, photos, hit lists and sends are deleted from
the server. Spots on this phone stay until you remove them.', [Cancel, { text: 'Delete', style: 'destructive' }])` →

### The function — `supabase/functions/account-delete/index.ts`

Deno, `Deno.serve`; `import { createClient } from 'npm:@supabase/supabase-js@2.118.0'`; `corsHeaders` from
`supabase/functions/_shared/cors.ts`. `OPTIONS` → 200 with CORS. Else:
1. `Authorization: Bearer <jwt>` missing → **401** `{ error: 'unauthorized' }`. Anon client (`SUPABASE_URL`,
   `SUPABASE_ANON_KEY` env, injected by the runtime) `auth.getUser(jwt)`; error/no user → 401. The uid comes **only**
   from that user; the request body is never read.
2. Admin client (`SUPABASE_SERVICE_ROLE_KEY`, `{ auth: { persistSession: false, autoRefreshToken: false } }`).
   Collect paths: `storage.from('photos').list(uid)` → each spot folder `list('<uid>/<spot>')`; `from('sends')
   .select('id').eq('sender', uid)` → `list('sends/<id>')`; page with `{ limit: 1000, offset }`. `remove(paths)` in
   chunks of 1000 (Storage API: a direct `DELETE` on `storage.objects` is blocked, S3 notes). Storage first: a retry
   after a later failure can still find the files; the reverse order would orphan them.
3. `auth.admin.deleteUser(uid)` → Postgres cascades `profiles` → spots, media, hit lists, list rows, memberships,
   friendships, blocks, sends, links (all `on delete cascade` in S3's schema; `uploaded_by`/`invited_by`/`used_by` set
   null). S7 must keep "a saved send's photos are copied into the recipient's own prefix" true (D40), so removing
   `sends/<id>/` never breaks a saved copy.
4. Any step's error → **500** `{ error: 'delete failed' }` (detail only in `console.error` server-side); ok → 200
   `{ ok: true }`. JSON + CORS headers on every response.

Config: keep the default `verify_jwt = true` for it. tsconfig gains `"exclude": ["node_modules", "supabase/functions"]`
and eslint `ignores` gains `supabase/functions/*` (Deno `npm:` imports and the `Deno` global break app tsc/lint). No
Deno binary: S4-05 records that `deno check` was not run; S4-06's integration test is the check.

### As built (S4-05)

- Profile: `AccountSection` in `app/(tabs)/profile.tsx`; no client **or** status `unconfigured` shows the unconfigured
  line (the store starts `signed_out` until `useAuthInit` runs). `needs_username` renders as signed in. One in-flight

- `src/sync/auth.ts`: `signOutOfAccount(client)` (`signOut()`; error or throw → `sessionStorage.removeItem(
  SESSION_STORAGE_KEY)`, S4-08; never rejects) and `deleteAccount(client)`
  (`functions.invoke('account-delete')`, POST by default; true only for `data.ok === true` with no error; a non-2xx is
  a `FunctionsHttpError` in `error`; a throw is false). Why the last step (Opus review, Important): offline with an
  expired access token, auth-js 2.118's `__loadSession` answers `{ session: null, error }` and leaves the session
  stored, so `_signOut` (either scope) returns that error before `_removeSession`; the next `TOKEN_REFRESHED` online
  would sign the rider back in. So the client now has a fixed `storageKey: 'hitlist.auth.session'`
  (`src/sync/session-storage.ts`); a dev phone signed in before this commit keeps an orphan keychain entry under the old
  derived key (`sb-100-auth-token`) and reads as signed out.
- Profile keys `AccountSection` on `userId`, so an old delete error or busy state never shows for the next account.
- Function: paging for `list` (1000) and for `sends` (`range`, PostgREST max_rows), recursive folders (`id === null`)
  listed 20 at a time in parallel, `remove` in chunks of 1000; sends **from or to** the rider (a send to them cascades
  away, and then nobody may remove its files); 405 for anything but POST/OPTIONS; 500 if a runtime env value is
  missing. Left: a photo uploaded between the listing and `deleteUser` stays in Storage (no row points at it).
- **No `deno check`** (no Deno on the box). Stand-in check instead: `tsc --noEmit` on the function with a `Deno`
  declaration and `npm:@supabase/supabase-js@2.118.0` mapped to `node_modules/@supabase/supabase-js` (strict, exit 0;
  a misspelt `deleteUserX` fails it). S4-06's integration test runs it for real.

Written answers (reviewer, each checked here with one command):

1. **No key or URL committed.** the feature's `git grep` for a JWT prefix (outside node_modules and the lockfile) prints
   only the feature list's own copy of that command; `git ls-files '.env*'` prints `.env.example` only; tests use

2. **The session never lands in AsyncStorage unencrypted.** The only AsyncStorage write is the AES-GCM ciphertext
   (`src/sync/session-storage.ts` `writeItem`); a small session goes to the keychain and the AsyncStorage entry is
   removed; a failed keychain write leaves ciphertext with an old or no key, never plaintext.
3. **The AES key is removed on sign-out**: `removeItem` deletes the keychain entry (the key) and the ciphertext
   together; auth-js's `_removeSession` and the offline/expired path in `signOutOfAccount` both go through it.

   deep link (`hitlist://spot/x`, `/list/x`, `/area`, `/add`, `/import`) opens that screen without onboarding, and back
