# S6 plan: friends and the Inbox tab

> **For agentic workers:** one harness session per feature (S6-02 … S6-07); each build feature commits its test file
> **RED first** (`S6-0n: RED …`, first run fails, note the failure in the message), then the code that makes it pass.

**Goal:** a signed-in rider adds a friend by exact @username, the other rider accepts or declines from a new Inbox tab
(badge = unseen items), either side removes the friendship, and a rider can block (and unblock) someone without them
being told. Signed out or unconfigured, Friends and Inbox say one line and offer Sign in; nothing else changes.

**Architecture:** the server side is done (S3-05, `supabase/migrations/20261023025214_friends_rls.sql` +
`20261023060000_review_fixes.sql`, pgTAP `050-friends-rls.test.sql`): `find_profile(p_username)`,
`send_friend_request(p_username)`, `respond_friend_request(p_id, p_action)`, `block_user(p_user)`,
`unblock_user(p_user)`, and RLS on `friendships` (either side selects/deletes), `blocks` (blocker only), `profiles`
(self, accepted friends, a rider who asked you, co-members). **No server migration in S6.** The client adds
`src/sync/friends.ts` (calls), `src/db/profiles.ts` (a local mirror of names, migration 6), `src/stores/friends-store.ts`,
`src/stores/inbox-store.ts` (kind-tagged items + seen mark), `app/friends/index.tsx`, `app/(tabs)/inbox.tsx`.

**Tech stack:** `@supabase/supabase-js` 2.118 (postgrest-js `rpc(fn, args)`, `from().select/delete`), expo-sqlite 57,
zustand 5, expo-router 57 (`useIsFocused`, already mocked `true` in `jest.setup.ts`). No new dependency.

**Spec:** §1 (Friends, Inbox), §3.3 (`profiles`, `find_profile`), §3.5, §5.6, §7 S6, D37, D39, D49, D50, D58, D63;
new D72–D75. **Diff base for the S6-07 review: `986ee98`** (HARNESS: S5 verified).

## Global constraints

- `src/sync/friends.ts` functions take `client` and `uid` and guard with `signedInAs(client, uid)`
  (`src/sync/account.ts`): no session for `uid` → resolve with nothing, no call (no app singleton or store inside, so the
  S6-05 integration test runs three riders' clients in one process). Only `applyFriends` and the screens read
  `useAuthStore`. After the network calls `refreshFriends` re-checks `maySync(db, client, uid)` (session **and**
  `sync_state.user_id = uid`) before writing the mirror and `signedInAs` before `applyFriends`: a sign-out, an account
  switch, a pending switch confirm (`needs_confirm`) or a session that fell back to anon mid-load (anon reads 0
  `friendships` rows with no error) drops the result instead of wiping the store or filling the wrong account's mirror.
- **Only the newest load applies:** a module-level ticket per uid; `refreshFriends` takes one before its first call and
  applies only if it is still the newest (a load started before Accept that ends after it would put the request back).
- **No enumerating riders:** the app never selects `profiles` without an `.in('id', ids)` / `.eq('id', id)` filter,
  and those ids come from the rider's own `friendships` rows. Usernames reach the app only from `find_profile` (one
  exact name the rider typed) and from those rows.
- **A blocked rider is never told (D50):** 'not found', 'they blocked you' and `send_friend_request`'s `P0002` all map
  to the same `{ found: false }` and the same copy 'No rider named @x'.
- Usernames typed by the rider: trim, drop one leading `@`, lowercase; must match `^[a-z0-9_.]{3,20}$` (D39) before
  any call (an invalid name makes no call).
- Server errors are `console.warn` (Jest's zero `console.error` rule); the UI shows fixed copy only.
- The badge counts only items **addressed to** the rider (a friend request with `requested_by ≠ uid`; S7: sends with
  `recipient = uid`; S8: invitations with `user_id = uid`), never anything the rider created.
- Accept / Decline / Cancel / Remove / Block / Unblock are single-flight per row: a `useRef<Set<string>>` of busy ids,
  checked synchronously before the call (a double tap sends one rpc); the row shows a spinner while busy.
- Timestamps from the server go through `toIso` (`src/sync/time.ts`) before they are stored or compared.
- `npx expo lint && npx tsc --noEmit && npx jest --silent` green after every feature.

## Data (S6-02) — `src/sync/friends.ts`, `src/stores/friends-store.ts`

```ts
export interface FriendProfile { id: string; username: string | null; display_name: string | null }
export interface FriendRow { friendshipId: string; created_at: string; profile: FriendProfile } // profile.id = the other rider
export interface FriendsData {
  friends: FriendRow[];   // status 'accepted', by username
  incoming: FriendRow[];  // 'pending', requested_by ≠ uid, newest first
  outgoing: FriendRow[];  // 'pending', requested_by = uid, newest first
  blocked: FriendProfile[]; // blocks where blocker = uid (D74), names from the local mirror
}
export type AddResult =
  | { status: 'invalid' }                         // failed the D39 pattern; no call made
  | { found: false; status: 'not_found' }          // unknown, they blocked you, not onboarded, or P0002 on send
  | { found: true; status: 'self' | 'already_friends' | 'already_sent' | 'blocked_by_me' | 'sent' | 'accepted';
      profile: FriendProfile };

loadFriends(client, uid): Promise<FriendsData>
addFriend(client, db, uid, typed): Promise<AddResult>
respond(client, friendshipId, action: 'accept' | 'decline'): Promise<void>
removeFriend(client, friendshipId): Promise<void>      // also Cancel of a sent request
block(client, userId): Promise<void>
unblock(client, userId): Promise<void>
refreshFriends(db, client, uid): Promise<void>         // loadFriends → upsertProfiles → applyFriends; errors → console.warn
normaliseUsername(typed): string | null
```

- **loadFriends** = two-step join, RLS decides the rows (no `.or` filter needed: `friendships_select` returns only rows
  the rider is in):
  1. `from('friendships').select('id,user_a,user_b,status,requested_by,created_at').gt('id', last).order('id').limit(500)`
     paged by id until a short page (PostgREST caps at 1000);
  2. `from('blocks').select('blocked,created_at').order('blocked').limit(500)` (same paging);
  3. the other side of each row = `user_a === uid ? user_b : user_a`; `from('profiles').select('id,username,display_name')
     .in('id', chunk)` in chunks of 100 for every other id. RLS returns friends and askers; **a sent request's target
     and a blocked rider are not readable** (S3 rule: the asker must not follow a rename): loadFriends returns them
     with `username: null` and `refreshFriends` fills those from the local mirror (`getProfiles`); still unknown →
     'A rider you asked' (D73).
  Any error → throw (the caller warns; the store keeps its last data).
- **addFriend(typed)**: `normaliseUsername` (null → `invalid`) → `rpc('find_profile', { p_username })` (no row →
  `not_found`) → upsert that profile into the local mirror (the rider typed it; this is how a sent request keeps its
  name) → `id === uid` → `self` → `from('friendships').select('id,status,requested_by').eq('user_a', least).eq('user_b',
  greatest).maybeSingle()` (`accepted` → `already_friends`; pending by me → `already_sent`) → `from('blocks')
  .select('blocked').eq('blocked', id).maybeSingle()` (row → `blocked_by_me`, no send) →
  `rpc('send_friend_request', { p_username })` (error `P0002` → `not_found`; other errors throw) → `accepted` if a
  pending row by them existed (the function accepted it), else `sent`. Then `refreshFriends`.
- **respond**: `rpc('respond_friend_request', { p_id, p_action })`; error `42501` ('no friend request to answer': answered
  or withdrawn elsewhere) resolves (the refresh drops the row); others throw. **removeFriend**:
  `from('friendships').delete().eq('id', id)`. **block / unblock**: `rpc('block_user' | 'unblock_user', { p_user })`.
  Each ends with `refreshFriends`.
- **friends store** `src/stores/friends-store.ts` (not persisted): `{ userId, friends, incoming, outgoing, blocked,
  loadedAt, loadError }`; `applyFriends(uid, data)` (ignored unless `uid` = `useAuthStore` `userId`) sets them and calls
  `useInboxStore.getState().setItems('friend_request', incoming → items)`; `clearFriends()`.
- **Engine:** `syncOnce` calls the inner `loadAndApplyFriends(db, client, uid)` after the pull, inside its task and its
  try (an error is a `console.warn`; it never changes `lastError` or 'Backed up'). The Friends screen, the Inbox tab and
  every mutation call `refreshFriends` = `runExclusive(() => loadAndApplyFriends(…))`, so the mirror write never lands
  inside adopt's BEGIN/COMMIT or after its `DELETE FROM profiles` (a runExclusive task never awaits `syncNow` or
  `refreshFriends`; the engine uses the inner function).
- **Sign out / switch:** `use-auth-init` clears the friends and inbox stores whenever `userId` changes (sign-out, and
  signed_in(A) → signed_in(B) via the unknown-user `TOKEN_REFRESHED` path), not only when status leaves `signed_in`; the
  account switch in `adopt`, `removeLocalAccountData` and `releaseAccountData` also `DELETE FROM profiles` (D72).
- **Mapping server errors:** `send_friend_request` `P0002` → `not_found`; `42501` ('unblock this user first', a block
  added on another phone after the pre-check) → `blocked_by_me`. `respond` `42501` resolves as 'already answered' only
  when `signedInAs` still holds (else it is 'not signed in': throw). `block_user` `P0002` (target deleted their account)
  → refresh, no alert. Anything else throws → "Couldn't reach the server. Try again." + `console.warn`.
- **Fake client** (`src/__tests__/helpers/fake-supabase.ts`, copy from `node_modules/@supabase/postgrest-js/dist/*.d.mts`):
  add `rpc(fn, args?)` → thenable `{ data, error }`; `rpcs: { fn, args }[]` log; `rpcHandlers[fn] = (args) => ({ data,
  error })` (`find_profile` returns a table: its handler answers an **array**, `[]` for no hit); `failNext('rpc',
  error)`; `friendships`/`blocks` answer from `tables` like pull's tables (`eq`, `gt`, `in`, `order`, `limit`,
  `maybeSingle`). **Rewrite the `profiles` branch**: today it skips `selects` (`run`: `table !== 'profiles'`) and
  applies only `eq`; it must log every profiles select in `selects`, apply `in`, and filter by a test-set
  `readableProfiles` (mimics RLS), keeping the S4 `eq('id').maybeSingle()` / `update` behaviour. Deletes on
  `friendships` logged in `calls`.

## Local cache (S6-02) — migration 6, `src/db/profiles.ts` (D72 *default*)

```sql
CREATE TABLE profiles (
  id TEXT PRIMARY KEY,      -- the server's profiles.id (auth uid)
  username TEXT,            -- NULL until onboarded (S4: S5+ must not assume a username)
  display_name TEXT
);
```
Appended to `MIGRATIONS` (length 6; 1–5 untouched; no trigger: never in the outbox, never pushed).
`upsertProfiles(db, rows)` = one `INSERT INTO profiles … SELECT … FROM json_each(?) ON CONFLICT(id) DO UPDATE SET
username = COALESCE(excluded.username, profiles.username), display_name = excluded.display_name`. Callers upsert only
rows the server actually returned (the `profiles` select and a `find_profile` hit), **never the null placeholders** of
unreadable outgoing/blocked rows (that would wipe a mirrored display name). `getProfiles(db, ids)` → `Record<id, FriendProfile>`.
`clearProfiles(db)`. Names show offline (Friends screen after a cold start shows the last loaded names once the store
is filled; S7 "From @name" and S8 owner badges read the same table). The friends list itself is not stored locally in
S6: offline the screens show the mirror-backed rows from the last `refreshFriends` of this session, else the empty
state plus "Couldn't reach the server. Pull to try again."

### Inbox tab (S6-04) — `app/(tabs)/inbox.tsx`, `src/stores/inbox-store.ts`

```ts
type InboxItemBase = { id: string; created_at: string };          // created_at = toIso(server time)
export type InboxItem =
  | (InboxItemBase & { kind: 'friend_request'; friendshipId: string; from: FriendProfile })
  // S7 adds | (InboxItemBase & { kind: 'send'; … }); S8 adds | (InboxItemBase & { kind: 'invite'; … })
  ;
state: { userId; items: InboxItem[]; seenAt: string | null | undefined }
setItems(kind, items)       // replaces that kind's items only
markSeen(db, uid)           // seenAt = max(seenAt, newest item created_at) → setSyncState(`inbox_seen_at:${uid}`)
loadSeen(db, uid)           // at sign-in
selectUnseenCount(s)        // seenAt undefined → 0; else items.filter(i => s.seenAt === null || i.created_at > s.seenAt).length
clearInbox()
```
- The seen mark is the newest **server** `created_at` seen, not the phone's clock (a phone clock ahead of the server
  would hide new requests). Keyed per rider (`inbox_seen_at:<uid>`, like `last_sync_at:<uid>`).
- `seenAt` is `undefined` until loaded (badge 0: never count everything on launch), `null` when loaded and never set.
  `applyFriends` awaits `loadSeen(db, uid)` before the first `setItems` for that uid (a cold start with a stored
  session fires no `SIGNED_IN`, so nothing else would load it). `markSeen` writes max(stored, newest), never backwards.
- Focusing the tab (`useIsFocused()` true) **while AppState is `'active'`** with items calls `markSeen`; items arriving
  while it is focused and active are marked too (effect on `[isFocused, appActive, items]`; a request that arrives in
  the background stays unseen). No per-row read state (D75).
- Sections in a fixed order by kind, each from a `renderItem` switch with an exhaustive `never` check: **Friend
  requests** (S6), **Spots sent to you** (S7), **Invitations** (S8). Row: '@ana wants to be friends' (display name as
  the second line when set) + **Accept** / **Decline** → `respond(id, …)`; long press → 'Block @ana' (same confirm as
  Friends). Failure → `Alert.alert("Couldn't reach the server", 'Try again.')`.
- Empty → 'Nothing here yet' + 'Spots friends send you, hit list invitations and friend requests show up here.'
- Signed out → 'Sign in to get spots from friends' + 'Sign in'; unconfigured → "Accounts aren't set up in this build".
- On focus and pull-to-refresh → `refreshFriends`.

## Integration test design (S6-05) — `src/__integration__/friends.test.ts`

Real clients against the local stack, node:sqlite for the mirror. Riders via `createRider(uniqueUsername('ana'|'ben'|
'cal'))` (names are prefixed and unique per run, so 'BEN' = `ben.username.toUpperCase()`).
1. `addFriend(ana, 'BEN')` → `{ found: true, status: 'sent' }`; ben's `loadFriends` has one `incoming` with ana's username;
   ana's has one `outgoing` (name from ana's mirror).
2. `respond(ben, id, 'accept')`; both `loadFriends` list the other in `friends` with username.
3. ana and cal become friends (`addFriend(ana, cal)`, cal accepts); ana's `from('profiles').select().eq('id', cal.id)`
   → cal's row (control). cal blocks ana: the friendship row is gone for both (`loadFriends` of each has no other);
   ana's profile select → no row; `addFriend(ana, cal)` → `{ found: false }`; cal's `loadFriends().blocked` = [ana].
4. `addFriend(ben, 'nobody_' + suffix)` → `{ found: false }`; `addFriend(ana, ana.username)` → `self`.
5. ben `removeFriend` → both `friends` lists empty; cal `unblock`s ana → `addFriend(ana, cal)` finds cal again.
6. `afterAll`: `deleteRider` ×3; run twice in a row → green both times.
Commands (S6-05): `npm run db:start && npm run db:reset && npm run test:db && npm run test:integration && npm run db:stop`;
record the counts here; `docker ps --format '{{.Names}}'` shows no `supabase_*_hit-list` afterwards.

## Known limit (D50, not a bug for S6-07 to chase)

A blocked rider can infer a block: a name that said 'Request sent' before now says 'No rider named @cal', and their
phone's mirror still holds the blocker's name. That is inherent to `find_profile` with unique usernames (§9 Q19). What
S6 guarantees: the copy and the result are the same as for a name that doesn't exist, and no screen shows a mirrored
name for a rider who isn't in the current `friendships`/`blocks` rows.
