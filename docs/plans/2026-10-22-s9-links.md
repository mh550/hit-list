# S9 plan: Links (send links with no login, invite links that need an account)

> **For agentic workers:** one harness session per feature (S9-02 … S9-07); each build feature commits its test file
> **RED first** (`S9-0n: RED …`, first run fails, note the failure in the message), then the code that makes it pass.

**Goal (D44, D45, spec §3.6):** the Send sheet gets **Copy link instead**: a one-time copy of the spots that anyone
holding the link can look at in a browser, with no account, until it expires (1 day / 7 days / **30 days** / never) or
the sender revokes it from Sent. A shared list's owner makes an **invite link** (7 days, single use, one role) from the
members screen and revokes it there. Expo Go can't open universal links, so the Inbox gets **Paste a link**: an invite
link joins the list, a send link opens its page. The page is one static file plus one script (`web/share/`); its data
comes from the `share-preview` Edge Function as JSON (Edge Functions can't serve HTML, D45).

**Architecture:** the server side of links already exists (S3-07, `supabase/migrations/20261023041500_links.sql`,
pgTAP `080-links-rls`): table `links (id, kind, token_sha256, send_id | list_id, role, created_by, expires_at,
revoked_at, used_by, used_at)` with RLS on and no policies; `create_link(p_kind, p_target, p_token_sha256,
p_expires_at, p_role)` → uuid; `revoke_link(p_id)`; `list_my_links(p_kind)`; `preview_link(p_sha)` (service role only,
one empty answer for every dead case); `redeem_invite(p_token)` → list id (single use under a row lock, D60: owner and
existing members get the id and nothing changes); `t30_revoke_invite_links` (stop sharing / delete). `create_send`
already takes `p_recipient` NULL (a link-only send, S3 schema comment). S9 adds **one server migration** (S9-02, see
Server), the `share-preview` function, `src/utils/link-token.ts`, `src/sync/links.ts`, the UI pieces and `web/share/`.

**Tech stack:** expo-crypto 57 (`getRandomBytes`, `digestStringAsync`, `CryptoDigestAlgorithm.SHA256`,
`CryptoEncoding.HEX`), **expo-clipboard ~57.0.2** (new, S9-01 `chore:` commit e3620d4; `setStringAsync(text):
Promise<boolean>`), `Linking.openURL` (react-native), supabase-js 2.118 (`rpc`, `functions.invoke`), Deno edge runtime
(`npm:@supabase/supabase-js@2.118.0`, Web Crypto), jest-environment-jsdom (already in `node_modules` via jest-expo).

## Global constraints

- **The plain token never sits server-side.** The server stores only `token_sha256` (lowercase hex). The URL carries
  the token in the **fragment** (`#t=`), so the static host never sees it in a request or log. The page sends it to
  `share-preview?t=` (spec §3.6, the feature steps) and `redeem_invite(p_token)` hashes it in SQL: both reach Supabase
  only, which holds the data anyway, and neither stores it. Never log a token (no `console.*` with it, app or function).
- **One "gone" for everything dead.** Unknown, malformed, expired, revoked, withdrawn, used (invite), unshared or
  deleted list: `404`, body exactly `{"error":"gone"}`, the same headers. Never say which (§3.6).
- **A send link shows exactly the frozen payload** (D40): no read of `spots`/`media`; fields by an allow-list, never a
  spread of the payload (the payload's `id` is the sender's spot id: not shown).
- **Signed photo URLs live 600 s** and are made only for objects **listed** under `sends/<send_id>/` (Storage `list`)
  that a payload photo names, never for a payload path as written (the S3-07 comment on `preview_link`: the service
  role would sign anyone's photo for a path the sender wrote).
- **D34 words:** link UI in the Send sheet and Sent says **Send / link / Copy link**, never Share; the members
  screen's invite link says **Invite link**, never Send. The existing source-reading tests keep holding.
- **Accounts are optional:** Copy link, invite links and Paste a link need a signed-in rider with a username; signed
  out the Inbox shows its existing Sign in line and no Paste row.
- Every timestamp to the server through `toIso`; ids from `newId()`; no `uuid`, no `Buffer`, no `URL.searchParams`
  in app code (Hermes' `URL` lacks most of it): tokens are parsed with a regex.

## Tokens — `src/utils/link-token.ts` (S9-03)

- `newToken(): string` = `getRandomBytes(16)` (128 bits, D45) as **base64url** without padding, 22 chars of
  `[A-Za-z0-9_-]`; a hand-written encoder (no `btoa`/`Buffer` dependence).
- `tokenHash(token): Promise<string>` = `digestStringAsync(SHA256, token, { encoding: HEX })`, `.toLowerCase()`
  (the SQL checks `^[0-9a-f]{64}$`; `redeem_invite` hashes the UTF-8 text the same way; base64url is ASCII).
- `linkUrl(base, token)` = `` `${base}#t=${token}` `` (base used verbatim; the default ends in `/`).
- `parseToken(text): string | null`: trim; a bare token `^[A-Za-z0-9_-]+$` → itself; else the first
  `[#?&]t=([A-Za-z0-9_-]+)` → the group; else null (`'https://x.test/other'` → null).
- `TOKEN_RE = /^[A-Za-z0-9_-]{22}$/` exported for the function's and page's format check (each keeps its own copy:
  Deno and the page don't import app code).
- Jest: `jest.setup.ts`'s expo-crypto mock gains `digestStringAsync` (Node `createHash`, hex or base64 per
  `options.encoding`), `CryptoDigestAlgorithm` and `CryptoEncoding` enums, names copied from
  `node_modules/expo-crypto/build/Crypto.d.ts` / `Crypto.types.d.ts`.

## share-preview — `supabase/functions/share-preview/index.ts` (S9-02)

- `config.toml`: `[functions.share-preview] verify_jwt = false` (a browser with no account calls it) and
  `[functions.account-delete] verify_jwt = true` (explicit, today's default).
- `OPTIONS` → 204 with CORS; anything but `GET` → 405 `{ error: 'method not allowed' }`. Own headers (not
  `_shared/cors.ts`, which allows POST): `Access-Control-Allow-Origin: *`, `Access-Control-Allow-Methods: GET,
  OPTIONS`, `Content-Type: application/json`, `Cache-Control: no-store`, `Referrer-Policy: no-referrer`. JSON only,
  never `text/html`.
- `t` from `new URL(req.url).searchParams`; not matching `^[A-Za-z0-9_-]{22}$` → gone **without** a database call.
- `sha = hex(await crypto.subtle.digest('SHA-256', new TextEncoder().encode(t)))`, lowercase.
- Service-role client (`SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` from the runtime env; `auth: { persistSession:
  false }`) → `rpc('preview_link', { p_sha: sha })`; 0 rows → gone; an rpc error → 500 `{ error: 'unavailable' }`
  (detail only in the log, never the token).
- `kind 'send'`: parse `payload.spots` defensively; each spot → `{ name, generated_name, lat, lng, feature_types,
  stopped, natural_speed, notes, photo_urls }` (missing/wrong-typed fields → null/[]/false); `storage.from('photos')
  .list('sends/<row.send_id>')` (paged), keep the payload photos whose `<media_id>.jpg` is in that listing, then one
  `createSignedUrls(paths, 600)` for all; an entry with an error is left out.
- **Signed URL origin:** storage-js builds each URL from the client's `SUPABASE_URL`, which in the local edge runtime
  is the internal gateway (`http://kong:8000`, confirm first in S9-02). The function rewrites the origin to
  `PUBLIC_SUPABASE_URL` (set in `[edge_runtime.secrets]` in `config.toml` to `http://127.0.0.1:54321` locally, not a
  secret; the live checklist sets the Tailscale or cloud value), falling back to `SUPABASE_URL` when unset (the cloud's
  is public). Test: the returned URL's origin is `http://127.0.0.1:54321` and it fetches 200. Answer `200 { kind: 'send', spots, sender: { username, display_name },
  expires_at }` (sender from the `preview_link` row, never the payload's).
- `kind 'invite'`: `200 { kind: 'invite', list_name, inviter: { username, display_name }, expires_at }`, no spots.
- Gone body is built once (`const GONE = JSON.stringify({ error: 'gone' })`) so the four dead cases are byte-identical.
- Reload note: the local edge runtime doesn't reload an edited function (`docker restart
  supabase_edge_runtime_hit-list`); an edited `config.toml` (`verify_jwt`, `[edge_runtime.secrets]`) needs
  `npm run db:stop && npm run db:start`.
- Risk to check in S9-02: `preview_link` tests `auth.jwt() ->> 'role' = 'service_role'`; the runtime's service key
  must reach PostgREST as that role (if the CLI provides only `sb_secret_…` keys, the gateway mints the JWT; the
  integration test is the proof).

## Client — `src/sync/links.ts` (S9-03)

All take `(client, uid, …)` or `(db, client, uid, …)` like `lists.ts` (the feature steps' `createSendLink(sendId,
'30d')` / `redeemInvite(token)` shapes leave these out; the tests use these signatures), return null without a session for `uid` (`signedInAs` / `maySync`),
throw `serverError` otherwise; `LinkGoneError` for 42501 'invalid invite' and a 404 gone preview.

- `createSendLink(client, uid, sendId, expiry: '1d' | '7d' | '30d' | 'never')` → URL. `token = newToken()`,
  `rpc('create_link', { p_kind: 'send', p_target: sendId, p_token_sha256: await tokenHash(token), p_expires_at:
  expiry === 'never' ? null : new Date(Date.now() + days * 864e5).toISOString() })` → `linkUrl(shareBaseUrl(), token)`.
- `createInviteLink(client, uid, listId, role: 'add' | 'view')` → URL; `p_expires_at` = now + 7 d, `p_role`.
- `revokeLink(client, uid, linkId)` → `rpc('revoke_link', { p_id })`.
- `listMyLinks(client, uid, kind: 'send' | 'invite')` → `rpc('list_my_links', { p_kind })` mapped to `MyLink { id,
  kind, sendId, listId, role, createdAt, expiresAt, usedBy: { id, username } | null, status }` with `status`:
  `revoked_at` → 'revoked'; else `used_at` → 'used'; else `expires_at <= now` → 'expired'; else 'active'.
- `previewLink(client, token)` → `{ kind: 'send' | 'invite', listName?, … }`; `client.functions.invoke(
  'share-preview?t=' + token, { method: 'GET' })`. A non-2xx is `{ data: null, error: FunctionsHttpError, response }`
  (functions-js 2.118): `error.context.status === 404` (or `response?.status`) → `LinkGoneError`; a
  `FunctionsFetchError` (no status) → a plain failure. **The fake needs work first** (`fake-supabase.ts:400`: today
  `invoke` ignores its name, logs nothing and always answers `{ ok: true }`): log `{ name, options }` in a new
  `fake.invokes`, an `invokeHandlers[name]` answer hook, and failures shaped like `FunctionsHttpError` (`name`,
  `context: { status, json() }`) copied from `node_modules/@supabase/functions-js/dist/module/types.d.ts`.
- `redeemInvite(db, client, uid, textOrToken)` → list id: `parseToken` (null → `LinkGoneError`), `rpc('redeem_invite',
  { p_token })`, then `syncNow(db)` (outside any `runExclusive` task) so the list and its spots arrive; 42501 →
  `LinkGoneError`. Single-flight per token like `joinList`.
- Link-only send: a new `createLinkSend(db, client, uid, { spotIds, sender })` in `sends.ts`, sharing `createSend`'s
  internals (same 0/100-spot checks, D78 `NotBackedUpError`, photo staging), makes **one** send with
  `p_recipient: null` and returns `{ sendId, photoPaths }` (throws on failure; there is no friend for
  `SendResult.failed.to`). `createSend` keeps refusing `recipientIds: []` (`sync-sends.test.ts:249` stays).
  **D94 *default***. (The S9-03 step says "createSend with recipientIds []": see Proposed changes 7.)
- If `create_link` fails after the send went in: `withdrawSend({ id: sendId, photoPaths })` (best effort) and rethrow.
- `listSent` stays friends-only; `listSentLinks(db, client, uid)` lives in `sends.ts` (it needs the private
  `payloadPhotoPaths`) = `list_my_links('send')` joined with the rider's recipient-NULL sends → `SentLink { id, sendId,
  count, status, expiresAt, photoPaths, withdrawn }`; `useSentSends` returns both.
- **Revoke a send link** (D93 *default*): `withdrawSend` of its link-only send **first** (`preview_link` already hides
  a withdrawn send, so the link is dead from here; photos removed; `55000` can't happen: nobody saves a link-only
  send), then `revokeLink`. A row whose send is withdrawn but whose link isn't revoked reads 'Revoked' and retries the
  revoke quietly on the next load. An expired link's send keeps its photos until Revoke or Delete account
  (`account-delete` already removes `sends/<id>/` for every send of the rider, recipient or not).
